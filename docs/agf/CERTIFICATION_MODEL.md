# Agent Factory / IOS / Brain / CMD / Laurentia — Certification Model (shared)

## Evidence chain

Same shape as every prior corpus (`docs/gmd/`, `docs/wal/`,
`docs/fms/`, `docs/frk/`): référentiel modules → N1 (formative bank) →
N2 (applied cases) → assessment artifact → correcteur → (jury on
borderline scores) → Skill ID record.

## N1/N2/assessment structure

- **N1**: formative quiz bank. For `external/` formations, sourced
  against real, named industry standards/disciplines. For `internal/`
  formations, sourced strictly against the named file/route/schema
  cited in that formation's `REFERENTIAL.md` — never a memorized
  summary of generic agent-infrastructure concepts.
- **N2**: 2-3 applied cases, each with an eliminatory rule for any
  invented capability — a candidate who claims this Academy's
  `agent_factory.py` implements multi-agent orchestration, or that any
  of the 4 real external repos is wired to `CVL-ACADEMY`, fails the
  case by design.
- **Assessment**: a real artifact (annotated persona-config table, a
  command-center route-literacy exercise, an ADL-schema reading
  exercise) checkable against the real code/schema — never invented
  facts.

## Skill ID namespace

`AF16.SKILL.*`, `AF17.SKILL.*`, `AFX03.SKILL.*`, `BRN15.SKILL.*`,
`IOS07.SKILL.*`, `CMD15.SKILL.*`, plus one namespace per external
cluster (`AF0103.SKILL.*`, `AF0415.SKILL.*`, `LAU0110.SKILL.*`,
`BRN0114.SKILL.*`, `CMD0114.SKILL.*`) — reserved in `70_EVIDENCE/
EVIDENCE_ARCHITECTURE.md` once each formation is deepened.

## Authorization gate

Passing any assessment in this corpus never grants real access to
`agent_factory.py`/`ai_assistant.py`/`events.py` in production, nor
any access whatsoever to `CVLNAgentfactory`, `Cvln-ios-v.1`,
`Laurent.ia`, or `MetaCVLN` — none of which this Academy has any
observed relationship with. Certification is on literacy alone, per
`00_GOVERNANCE/AUTHORIZATION_MODEL.md`.

## Renewal cycle

Standard 24 months for all formations in this corpus. None handle
sensitive financial/ledger integrity.

## Never claim FULLY_COMPLETE

No formation in this corpus is `FULLY_COMPLETE` until a real candidate
has been assessed, a jury/corrector verification performed, and
evidence actually recorded — none of which this drafting pass
performs, even for CMD-15 (this wave's `PACKAGE_COMPLETE` flagship).
