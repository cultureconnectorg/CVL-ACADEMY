# CVE-01→15 — Canonical Education Map

## Shared competency skeleton

Every CVE-0X formation follows the same shape:
`METHODOLOGY_SECTION → CONCEPTS → COMPETENCIES`, grounded in a named
section of `KORA_CVE_Specification_Mathematique_v1.0.md`, with any
concept the spec names but does not fully derive flagged explicitly
as `FORMALIZATION_PENDING` (never invented to fill the gap).

## Anti-fabrication verification (mandatory before certifying any CVE-0X)

Before crediting a candidate with any CVE-0X competency, verify the
claimed formula/concept against the actual section cited in the
corresponding `REFERENTIAL.md` — never against a memorized summary of
"how a value-attribution system typically works." Two formations
(CVE-06, CVE-08) name concepts the frozen spec references or implies
but does not derive — a candidate must recognize and state this gap
explicitly, never invent a formula to fill it. This is this corpus's
own version of the `UNPROVEN_FEATURE` discipline, applied to
mathematics rather than code.

## Boundary note — never merge with `Cvln-ios-v.1/economics/CVE-v1.2.md`

Re-stated from `WALLET_CVE_RECONCILIATION.md`'s naming-collision guard:
this corpus teaches the KORA **Cultural Value Engine** (Trust Score,
CES, Nebula, UVC allocation). A different document,
`Cvln-ios-v.1/economics/CVE-v1.2.md`, describes a **CVLN Value
Engine** (JCC/contribution recognition, self-labeled
`TARGET`/`SPECIFICATION`) — a distinct system that happens to share
the same three-letter acronym. Never blended into this corpus.

## Certification / mission eligibility doctrine

Certification eligibility follows `CERTIFICATION_MODEL.md`'s N1/N2/
assessment structure. Mission eligibility for any CVE-0X role depends
on the real KORA product's own calibration/simulation/prototyping
roadmap (chantiers 2 and 3, not yet performed per the spec's own
status line) — no CVE-0X formation grants operational authority over
a live CVE calculation today; that stays a separate, future,
human-governed decision.
