# CVE-06 — Banque N2 (cas appliqués)

## Cas N2-1 — Formule Shapley présentée comme méthodologie KORA

Un candidat écrit une formule de valeur de Shapley et l'attribue au
"CVE de KORA." Corrige.

**Critères de notation:** rappelle que le terme "Shapley" n'apparaît
nulle part dans `KORA_CVE_Specification_Mathematique_v1.0.md`
(vérification directe par recherche plein texte) et que le mécanisme
d'attribution réel est `C_i,c` (§1.2, CVE-03). **Élimination
automatique** — présenter une formule inventée comme méthodologie
KORA réelle est exactement le mode d'échec `FAKE_PROOF` que ce
Master Package existe pour empêcher, appliqué aux mathématiques.

## Cas N2-2 — "Implémentons Shapley dès maintenant"

Un manager demande pourquoi ne pas implémenter Shapley immédiatement
"puisque c'est un standard du marché." Corrige.

**Critères de notation:** distingue clairement le concept général
(légitime, standard de marché, expliqué en M1) de son absence de
formalisation dans le CVE réel — propose que cela nécessiterait une
nouvelle révision de spécification ou un travail de chantier 2/3, pas
une implémentation immédiate sur la base du document figé actuel. Pas
d'élimination si le candidat distingue bien les deux, mais élimination
s'il affirme que le document actuel suffit à l'implémenter.

## Cas N2-3 — Référence Shapley alléguée en note de bas de page

Un collègue affirme avoir vu "Shapley" mentionné dans une note de bas
de page du document. Corrige.

**Critères de notation:** réaffirme la vérification directe par
recherche plein texte cette session — le terme n'apparaît nulle part
dans le document, notes de bas de page incluses (le document n'en
contient d'ailleurs pas). Élimination si le candidat valide
l'affirmation sans re-vérifier.
