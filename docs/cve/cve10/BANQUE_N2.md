# CVE-10 — Banque N2 (cas appliqués)

## Cas N2-1 — "Comment fixer MD_c en euros ?"

Un directeur financier demande "quelle formule fixe la valeur en
euros de `MD_c` chaque cycle ?" Corrige.

**Critères de notation:** répond honnêtement que le document ne
définit **pas** comment la valeur monétaire réelle de `MD_c` est
déterminée — seulement comment un `MD_c` déjà fixé est distribué.
Élimination si le candidat invente un mécanisme de fixation de
`MD_c`.

## Cas N2-2 — Redistribution "gagnant-gagnant" proposée

Un manager propose une modification où plusieurs œuvres pourraient
toutes voir leur `UVC` augmenter simultanément sans qu'aucune autre ne
baisse, "pour que tout le monde gagne." Corrige.

**Critères de notation:** cite C1 (`Σ_i UVC_i,c = MD_c`, un pool fixe)
— dans un cycle donné, c'est structurellement à somme nulle ; une
hausse relative pour une œuvre implique une baisse relative ailleurs.
Élimination si le candidat valide la proposition sans signaler
l'incompatibilité avec C1.

## Cas N2-3 — Re-dérivation de la formule UVC

Un stagiaire re-dérive la formule `UVC_i,c` en détail dans sa réponse
CVE-10 au lieu d'y renvoyer. Corrige.

**Critères de notation:** rappelle que la formule est enseignée en
profondeur dans CVE-09 et doit être citée par référence ici — CVE-10
apporte l'angle politique de revenu, pas une seconde dérivation. Pas
d'élimination (pas une invention), mais note réduite pour duplication.
