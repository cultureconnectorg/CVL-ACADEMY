# KLT-07 — Banque N1

```
Répartition : notions, méthode, limites, éthique. Couvre uniquement les
6 compétences construites (C1-C3, C5-C7) — C4 BLOCKED, hors banque.
```

**Q-N1-01** (notions, C1) — Une licence, dans l'écosystème territorial
Kiltikonet, désigne :
`CORRECT_ANSWER` : l'autorisation formelle d'un opérateur à représenter
Kiltikonet sur un territoire donné.
`RATIONALE` : M01.
`DISTRACTOR_RATIONALE` : "un simple accord verbal" ignore le caractère
formel de la notion posée en M01.
`DIFFICULTY` : facile.

**Q-N1-02** (limites, C1) — Un réseau territorial Kiltikonet réel
existe-t-il aujourd'hui dans Academy ?
`CORRECT_ANSWER` : non — `NOT_CONNECTED` (`KLT-0001` §4).
`RATIONALE` : M01, en-tête `KILTIKONET_DEPENDENCY`.
`DISTRACTOR_RATIONALE` : "oui, en version limitée" contredit l'état réel
constaté dans ce repo.
`DIFFICULTY` : moyen.

**Q-N1-03** (notions, C2) — Concevoir un modèle de gouvernance interne
pour une association candidate relève :
`CORRECT_ANSWER` : de la décision de l'association elle-même, pas du
rôle réseau.
`RATIONALE` : M02.
`DISTRACTOR_RATIONALE` : "du responsable de déploiement, pour
accélérer le processus" est exactement l'erreur de frontière nommée en
M02.
`DIFFICULTY` : difficile.

**Q-N1-04** (méthode, C3) — Un dossier d'onboarding constitué équivaut-
il à une licence accordée ?
`CORRECT_ANSWER` : non — c'est une recommandation, la décision reste
distincte.
`RATIONALE` : M03.
`DISTRACTOR_RATIONALE` : "oui, si le dossier est complet" confond
constitution du dossier et décision finale.
`DIFFICULTY` : moyen.

**Q-N1-05** (méthode, C3) — La première étape d'un processus
d'onboarding structuré est :
`CORRECT_ANSWER` : lister les critères réels à vérifier pour ce
candidat.
`RATIONALE` : M03.
`DISTRACTOR_RATIONALE` : "rédiger directement la recommandation finale"
saute les étapes de vérification posées en M03.
`DIFFICULTY` : moyen.

**Q-N1-06** (éthique, C5) — Face à une fragilité déjà identifiée chez un
opérateur, la relation quotidienne doit :
`CORRECT_ANSWER` : maintenir la vigilance sur ce point, sans l'ignorer
par confort relationnel.
`RATIONALE` : M05.
`DISTRACTOR_RATIONALE` : "éviter d'en reparler pour préserver la
confiance" contredit directement la discipline posée en M05.
`DIFFICULTY` : difficile.

**Q-N1-07** (notions, C5) — Gérer une relation opérateur, ce n'est pas
seulement :
`CORRECT_ANSWER` : répondre aux demandes, sans vigilance sur les points
connus.
`RATIONALE` : M05.
`DISTRACTOR_RATIONALE` : "documenter chaque échange" n'est pas faux en
soi, mais n'est pas ce que M05 identifie comme insuffisant seul.
`DIFFICULTY` : moyen.

**Q-N1-08** (méthode, C6) — Une évaluation de faisabilité d'extension
territoriale doit :
`CORRECT_ANSWER` : croiser les fragilités réellement connues avec les
exigences réelles de l'extension.
`RATIONALE` : M06.
`DISTRACTOR_RATIONALE` : "s'appuyer sur des données de couverture
Network réelles" ignore que `C4` reste `BLOCKED` — cette évaluation
s'appuie sur ce qui est réellement disponible.
`DIFFICULTY` : difficile.

**Q-N1-09** (limites, C6) — Une recommandation de faisabilité doit
être :
`CORRECT_ANSWER` : nuancée, avec des conditions explicites si
nécessaire.
`RATIONALE` : M06.
`DISTRACTOR_RATIONALE` : "binaire (oui/non)" contredit l'exigence de
nuance posée en M06.
`DIFFICULTY` : moyen.

**Q-N1-10** (méthode, C7) — Un incident de périmètre de rôle (pas
technique) doit-il être documenté et remonté ?
`CORRECT_ANSWER` : oui — sa gravité potentielle n'est pas moindre qu'un
incident technique.
`RATIONALE` : M07.
`DISTRACTOR_RATIONALE` : "non, une correction directe suffit" ignore
l'exigence de documentation et de remontée posée en M07.
`DIFFICULTY` : moyen.
